# 血缘数据流全链路分析：从后端数据构建到前端 ECharts 图谱渲染

## 一、全局概览

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  MySQL   │───▶│  Entity  │───▶│Repository│───▶│ Service  │───▶│Controller│───▶│  Axios   │───▶│ ECharts  │
│ 数据库   │    │  实体层   │    │  数据访问 │    │  业务层   │    │  控制层   │    │ 请求层   │    │  渲染层   │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
  data_lineage    DataLineage    DataLineage     LineageService  LineageController  request.js     Lineage.vue
  data_table      DataTable      Repository      (核心转换)      (REST API)        (拦截/解包)    (chartOption)
  data_source     DataSource     DataTable
                 DataColumn      Repository
```

## 二、第 1 层：数据库（数据源头）

### 涉及表

| 表名 | 作用 | 关键字段 |
|------|------|---------|
| `data_lineage` | 存储血缘关系 | `source_table_id`, `target_table_id`, `source_column_id`, `target_column_id`, `lineage_type`, `transform_rule` |
| `data_table` | 数据表元信息 | `id`, `source_id`, `table_name`, `table_comment`, `table_type` |
| `data_source` | 数据源配置 | `id`, `name`, `type`, `host`, `port`, `database` |
| `data_column` | 数据列元信息 | `id`, `table_id`, `column_name`, `data_type` |

### 表间关系

```
data_source (1) ──▶ (N) data_table (1) ──▶ (N) data_column
                            │
                            ▼
                     data_lineage
                   (source_table_id ──▶ data_table.id)
                   (target_table_id ──▶ data_table.id)
```

### 初始数据示例（来自 init.sql）

```sql
-- user_info → dw_user_dim (ETL抽取转换)
-- order_info → dw_order_fact (ETL抽取转换)
-- user_info → ods_user_info (直接同步)
-- ods_user_info → dwd_user_info (清洗转换)
-- product_info → dw_order_fact (JOIN关联)
```

## 三、第 2 层：JPA 实体层（ORM 映射）

### DataLineage 实体

- 文件：`backend/src/main/java/com/lineage/entity/DataLineage.java`
- 映射表：`data_lineage`
- 核心字段：

```java
Long id;
Long sourceTableId;    // 源表ID（外键关联 data_table.id）
Long targetTableId;    // 目标表ID（外键关联 data_table.id）
Long sourceColumnId;   // 源列ID（可选，外键关联 data_column.id）
Long targetColumnId;   // 目标列ID（可选，外键关联 data_column.id）
String lineageType;    // 血缘类型: TABLE(表级) / COLUMN(列级)
String transformRule;  // 转换规则描述
String description;
Date createTime;
Long createBy;
```

> **注意**：实体层使用的是**逻辑外键**（`sourceTableId` 等 Long 类型字段），而非 JPA `@ManyToOne` 物理关联。这意味着关联查询需要手动在 Service 层完成。

- 文件：`backend/src/main/java/com/lineage/entity/DataTable.java`
- 核心字段：`id`, `sourceId`, `tableName`, `tableComment`, `columnCount`, `rowCount`, `tableType`

### DataSource 实体

- 文件：`backend/src/main/java/com/lineage/entity/DataSource.java`
- 核心字段：`id`, `name`, `type`, `host`, `port`, `database`

## 五、第 4 层：LineageService 业务层（🔥 核心数据转换节点）

- 文件：`backend/src/main/java/com/lineage/service/LineageService.java`

### 5.1 `getLineageGraph(Long tableId)` — 图谱数据构建主流程

这是整个数据流的**最关键转换节点**，将关系型数据转换为图结构数据：

```
步骤 1: 查询血缘关系
  lineageRepository.findAllByTableId(tableId)
  → List<DataLineage>  (原始血缘记录)

步骤 2: 收集关联表ID
  遍历 lineages，收集 sourceTableId + targetTableId → Set<Long> tableIds

步骤 3: 批量查询表信息
  tableRepository.findAllById(tableIds)
  → Map<Long, DataTable> tableMap  (tableId → DataTable)

步骤 4: 批量查询数据源信息
  从 tableMap 提取 sourceId → sourceRepository.findAllById(sourceIds)
  → Map<Long, DataSource> sourceMap  (sourceId → DataSource)

步骤 5: 构建 GraphNode 列表  ← 关键转换①
  DataTable → GraphNode
  ┌──────────────────────────────────────────────────────────────┐
  │ DataTable.id        → GraphNode.id       = "table_" + id    │
  │ DataTable.tableName → GraphNode.label    = tableName        │
  │ "table"             → GraphNode.type     = "table"          │
  │ DataTable.id        → GraphNode.tableId  = id               │
  │ null                → GraphNode.columnId = null              │
  │ DataSource.name     → GraphNode.sourceName                   │
  └──────────────────────────────────────────────────────────────┘

步骤 6: 构建 GraphEdge 列表  ← 关键转换②
  DataLineage → GraphEdge
  ┌──────────────────────────────────────────────────────────────────────┐
  │ DataLineage.id            → GraphEdge.id         = "lineage_" + id │
  │ DataLineage.sourceTableId → GraphEdge.source     = "table_" + id   │
  │ DataLineage.targetTableId → GraphEdge.target     = "table_" + id   │
  │ DataLineage.transformRule → GraphEdge.label                        │
  │ DataLineage.lineageType   → GraphEdge.lineageType                  │
  └──────────────────────────────────────────────────────────────────────┘

步骤 7: 组装返回
  return new LineageGraphDTO(nodes, edges)
```

### 5.2 `searchLineage(String tableName)` — 搜索入口

```
tableRepository.findByTableNameContaining(tableName)
  → List<DataTable> tables
  → getLineageGraph(tables.get(0).getId())  // 取第一个匹配结果
```

## 六、LineageGraphDTO 数据结构（前后端契约）

- 文件：`backend/src/main/java/com/lineage/dto/LineageGraphDTO.java`

```java
public class LineageGraphDTO {
    private List<GraphNode> nodes;
    private List<GraphEdge> edges;

    public static class GraphNode {
        private String id;          // "table_1"
        private String label;       // "user_info"
        private String type;        // "table"
        private Long tableId;       // 1
        private Long columnId;      // null
        private String sourceName;  // "MySQL生产库"
    }

    public static class GraphEdge {
        private String id;          // "lineage_1"
        private String source;      // "table_1"
        private String target;      // "table_5"
        private String label;       // "ETL抽取转换"
        private String lineageType; // "TABLE"
    }
}
```

### JSON 输出示例

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "nodes": [
      { "id": "table_1", "label": "user_info", "type": "table", "tableId": 1, "columnId": null, "sourceName": "MySQL生产库" },
      { "id": "table_5", "label": "dw_user_dim", "type": "table", "tableId": 5, "columnId": null, "sourceName": "PostgreSQL数仓" }
    ],
    "edges": [
      { "id": "lineage_1", "source": "table_1", "target": "table_5", "label": "ETL抽取转换", "lineageType": "TABLE" }
    ]
  }
}
```

## 七、第 5 层：LineageController 控制层（REST API）

- 文件：`backend/src/main/java/com/lineage/controller/LineageController.java`

| HTTP 方法 | 路径 | 方法 | 返回类型 | 说明 |
|-----------|------|------|---------|------|
| `GET` | `/api/lineage` | `getAllLineages()` | `Result<List<DataLineage>>` | 获取所有血缘关系（列表用） |
| `POST` | `/api/lineage` | `createLineage()` | `Result<DataLineage>` | 创建血缘关系 |
| `DELETE` | `/api/lineage/{id}` | `deleteLineage()` | `Result<Void>` | 删除血缘关系 |
| `GET` | `/api/lineage/graph/{tableId}` | `getLineageGraph()` | `Result<LineageGraphDTO>` | 获取图谱数据 |
| `GET` | `/api/lineage/search?tableName=xxx` | `searchLineage()` | `Result<LineageGraphDTO>` | 搜索血缘图谱 |

### Result 统一响应包装

```java
public class Result<T> {
    private Integer code;    // 200=成功, 500=失败
    private String message;  // "操作成功"
    private T data;          // 实际业务数据
}
```

## 八、第 6 层：前端 Axios 请求层（数据解包）

- 文件：`frontend/src/utils/request.js`

### 请求拦截器

```
注入 JWT Token → config.headers.Authorization = "Bearer {token}"
```

### 响应拦截器（🔥 关键解包节点）

```
response.data = { code: 200, message: "操作成功", data: LineageGraphDTO }
                                    ↓
判断 code === 200
  ├─ 是 → return res.data  ← 返回 LineageGraphDTO（自动剥离 Result 外壳）
  └─ 否 → ElMessage.error() + Promise.reject()
```

> **关键**：响应拦截器将 `Result<LineageGraphDTO>` 解包为 `LineageGraphDTO`，前端 API 调用方拿到的直接就是 `{nodes: [...], edges: [...]}`。

### API 函数

- 文件：`frontend/src/api/index.js`

```javascript
// 搜索血缘 → 返回 LineageGraphDTO
export function searchLineage(tableName) {
    return request({ url: '/lineage/search', method: 'get', params: { tableName } })
}

// 获取图谱 → 返回 LineageGraphDTO
export function getLineageGraph(tableId) {
    return request({ url: `/lineage/graph/${tableId}`, method: 'get' })
}
```

### 9.3 chartOption 计算属性（🔥 前端核心转换节点）

将 `LineageGraphDTO` 转换为 ECharts `graph` 系列配置：

```
GraphNode → ECharts Node
┌─────────────────────────────────────────────────────────┐
│ node.id          → { id: node.id }                      │
│ node.label       → { name: node.label }                 │
│ node.sourceName  → { sourceName: node.sourceName }      │
│ 固定值           → { symbolSize: 50 }                    │
│ 固定值           → { itemStyle: { color: '#5470c6' } }  │
│ 固定值           → { label: { show: true,               │
│                              position: 'bottom',        │
│                              fontSize: 12 } }           │
└─────────────────────────────────────────────────────────┘

GraphEdge → ECharts Edge
┌──────────────────────────────────────────────────────────────┐
│ edge.source → { source: edge.source }                        │
│ edge.target → { target: edge.target }                        │
│ edge.label  → { label: { show: true,                         │
│                           formatter: edge.label || '',       │
│                           fontSize: 10 } }                   │
│ 固定值      → { lineStyle: { color: '#91cc75',               │
│                               curveness: 0.2,                │
│                               width: 2 } }                   │
└──────────────────────────────────────────────────────────────┘
```

### 9.4 ECharts 完整配置结构

```javascript
{
  tooltip: {
    trigger: 'item',
    formatter: (params) => {
      // 节点: 显示表名 + 数据源
      // 边:   显示转换规则
    }
  },
  series: [{
    type: 'graph',           // 图类型: 关系图
    layout: 'force',         // 布局: 力导向
    data: [...],             // 节点数组
    edges: [...],            // 边数组
    roam: true,              // 允许缩放和拖拽
    force: {
      repulsion: 300,        // 节点间斥力
      edgeLength: 150        // 边长度
    },
    emphasis: {
      focus: 'adjacency',    // 高亮相邻节点
      lineStyle: { width: 4 }
    }
  }]
}
```

### 9.5 渲染绑定

```html
<v-chart ref="chartRef" class="chart" :option="chartOption" autoresize />
```

- `vue-echarts` 组件（`VChart`）作为 ECharts 的 Vue 封装
- 按需注册：`GraphChart`, `CanvasRenderer`, `TitleComponent`, `TooltipComponent`, `LegendComponent`
- `autoresize`：窗口变化时自动调整尺寸

## 十一、数据转换关键节点总结

| 序号 | 节点 | 位置 | 输入 | 输出 | 转换逻辑 |
|------|------|------|------|------|---------|
| 1 | **Repository 查询** | `DataLineageRepository` | `tableId` | `List<DataLineage>` | JPQL 联合查询 source/target |
| 2 | **Service 图构建** | `LineageService.getLineageGraph()` | `DataLineage` + `DataTable` + `DataSource` | `LineageGraphDTO` | 关系型数据 → 图结构（nodes + edges），ID 加前缀（`table_`/`lineage_`） |
| 3 | **Result 包装** | `LineageController` | `LineageGraphDTO` | `Result<LineageGraphDTO>` | 统一响应格式 `{code, message, data}` |
| 4 | **Axios 解包** | `request.js` 响应拦截器 | `Result<LineageGraphDTO>` | `LineageGraphDTO` | 剥离 `code`/`message`，仅返回 `data` |
| 5 | **ECharts 适配** | `Lineage.vue` chartOption | `LineageGraphDTO` | ECharts option | 添加视觉属性（颜色/尺寸/标签样式/力导向参数） |
